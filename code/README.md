# Тренажёр: пишем ML руками

> Этот каталог существует ради одного профиля читателя: **теорию понимаю, а руками пишу плохо**.
> Понимание и исполнение — разные навыки, и второй тренируется только исполнением.
> Здесь лежат скелеты функций и тесты к ним. Ваша задача — заполнить скелеты так, чтобы тесты позеленели.

## Быстрый старт

```bash
pip install -r code/requirements.txt

# посмотреть, что предстоит сделать (всё красное — это нормально)
pytest code/tests -q

# работать по одному файлу
pytest code/tests/test_metrics.py -v

# по одному тесту, с подробным выводом
pytest code/tests/test_metrics.py::test_roc_auc_with_ties -vv
```

## Что здесь есть

| Файл | Что реализуете | Норматив | Теория |
|---|---|---|---|
| `exercises/metrics.py` | confusion matrix, precision/recall/F1, ROC-AUC, Average Precision, DCG, NDCG | 55 мин | [метрики](../docs/02-classic-ml/04-metrics.md), [метрики рекомендаций](../docs/06-recsys/02-metrics-offline.md) |
| `exercises/models.py` | линейная регрессия, логистическая регрессия, KMeans, kNN | 55 мин | [линейные модели](../docs/02-classic-ml/02-linear-models.md), [кластеризация](../docs/02-classic-ml/10-clustering.md) |
| `exercises/attention.py` | устойчивый softmax, scaled dot-product attention, причинная маска, multi-head | 35 мин | [внимание и трансформер](../docs/03-deep-learning/04-attention-and-transformer.md) |

Нормативы — ориентир по времени на live-coding. На первом заходе будет дольше;
цель — довести до норматива за 2–3 повтора.

## Как работать, чтобы был толк

**1. Не смотрите в `solutions/` до собственной попытки.** Чтение готового решения ощущается
как обучение, но им не является. Единственный момент, когда решение полезно, — после того,
как вы написали своё и хотите сравнить подходы.

**2. Пишите с чистого листа, а не «допиливайте».** Скелет задаёт сигнатуру и подсказки,
всё остальное — ваше.

**3. Читайте тест как ТЗ.** Тесты написаны так, чтобы проверять именно те места, где обычно
ошибаются: совпадающие скоры в ROC-AUC, переполнение в сигмоиде, маскирование до softmax,
векторизация в kNN. Если тест непонятен — это сигнал, что в теории есть дыра.

**4. Повторяйте через день.** Первый раз вы решаете задачу. Второй раз — тренируете навык.
Разница между ними и есть то, что происходит на собеседовании.

**5. Засекайте время.** На собеседовании оно идёт. Без таймера вы тренируете не тот режим.

## Проверить, что виноват не тест

Если кажется, что реализация верная, а тест падает, — прогоните тесты против эталонных решений:

```bash
HANDBOOK_CHECK_SOLUTIONS=1 pytest code/tests -q
```

Всё должно быть зелёным. Если зелено — проблема в вашей реализации, если красно — в тесте
(и это баг, заведите issue).

## Типичные грабли, на которых спотыкаются здесь

| Симптом | Причина | Что делать |
|---|---|---|
| ROC-AUC расходится с sklearn на третьем знаке | не усреднены ранги совпадающих скоров | группировать одинаковые значения и давать им средний ранг |
| NaN в сигмоиде | `1/(1+exp(-z))` при больших отрицательных `z` | считать отдельно для `z >= 0` и `z < 0` |
| NaN после softmax | вся строка замаскирована в `-inf` | обработать случай нулевого знаменателя |
| Веса внимания не суммируются в 1 | маска применена после softmax | маскировать логиты до softmax |
| kNN не укладывается в таймаут | двойной цикл по объектам | раскрыть `‖a−b‖² = ‖a‖² − 2a·b + ‖b‖²` |
| KMeans каждый раз даёт разный результат | случайная инициализация без k-means++ | реализовать k-means++ и зафиксировать seed |
| Линейная регрессия расходится в `inf` | слишком большой learning rate | уменьшить шаг; условие сходимости — в [главе об оптимизации](../docs/01-math/04-optimization.md) |
