# Как дополнять хендбук

Этот хендбук написан как **учебник**, а не как сборник заметок. Поэтому у него есть жёсткий
авторский стандарт — [`.handbook/AUTHORING.md`](.handbook/AUTHORING.md). Прочитайте его перед
первым PR: там зафиксированы голос, структура главы, правила подачи формул, кода и вопросов.

## Что особенно ценно

| Тип вклада | Почему это важно |
|---|---|
| **Реальный вопрос с собеседования** | хендбук строится вокруг того, что спрашивают, а не вокруг того, что красиво звучит |
| **Разбор грабель из продакшена** | «симптом → причина → решение» — самая дефицитная часть любого учебника |
| **Уточнение формулы или вывода** | если где-то пропущен шаг, это баг |
| **Свежая статья/подход** | особенно в LLM, RecSys и инференсе, где всё меняется за месяцы |
| **Задача на код с критериями проверки** | практика — узкое место у большинства читателей |

## Правила для новой главы

1. Структура — строго по шаблону из `.handbook/AUTHORING.md`, §2.
2. Каждая формула — с расшифровкой всех обозначений; сквозная нотация из §4.
3. Вопросы «Проверь себя» — в формате `<details>`, с разбором «чего ждёт интервьюер» и «провал».
4. Ссылки — только на реально существующие материалы, с пояснением, зачем их читать.
5. Врезки уровня (🌱 / 🎯 / 🧠) и 💬 «на собеседовании» — вплетены по тексту, не свалены в конец.

## Правила для правки существующей главы

- Не ломайте сквозную нотацию и нумерацию файлов.
- Если добавляете вопрос — добавляйте вместе с разбором, а не голую формулировку.
- Если исправляете фактическую ошибку — по возможности приложите ссылку на источник.

## Технически

```bash
# локальный предпросмотр сайта
pip install mkdocs-material
mkdocs serve

# проверка ссылок и структуры
python tools/check_handbook.py
```

Работа над репозиторием ведётся через pull request'ы. Один PR — одна тема:
так его реально прочитать и обсудить.

## Ошибку нашли, а времени на PR нет?

Заведите issue с пометкой темы и цитатой куска, который вызывает вопрос. Это тоже вклад:
неточность в учебнике тиражируется дальше в головы читателей, поэтому чинить её важнее,
чем добавить ещё одну главу.
