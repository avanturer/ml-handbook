## Зачем это

Материалов по ML много, а связного пути к позиции **middle+ MLE** — почти нет. Курсы дают
широту без глубины, статьи — глубину без системы, а «100 вопросов для собеседования»
учат формулировкам вместо понимания и рассыпаются от первого уточняющего вопроса.

Этот хендбук построен иначе. Три принципа:

**Сначала проблема, потом решение.** Ни один метод не вводится словами «существует алгоритм X».
Сначала показано, что ломалось до него.

**Формулы выводятся, а не цитируются.** Каждый символ введён, каждый переход показан.
Именно на «очевидных» переходах люди теряют нить, поэтому пропусков нет.

**Вопросы с собеседований вплетены в объяснение.** Отдельного раздела с вопросами здесь нет —
и это осознанно. Врезки 💬 стоят там, где вы только что разобрали нужную теорию.
Прочитав главу подряд, вы проходите по всем вопросам, которые по этой теме задают.

## Как устроена глава

Структура одинакова во всех главах, поэтому ориентироваться легко:

```
Зачем эта глава        →  какую инженерную задачу закрывает
Карта главы            →  оглавление с однострочниками
1. Интуиция            →  проблема на конкретном примере, почти без формул
2. Формализация        →  строгая постановка, все обозначения введены
3. Вывод               →  математика по шагам, без пропусков
4. На практике         →  исполняемый код, реальные значения гиперпараметров
5. Компромиссы         →  когда метод правильный выбор, а когда его берут по инерции
6. Подводные камни     →  симптом → причина → что делать
7. Проверь себя        →  вопросы в формулировке интервьюера, с разбором
8. Практика            →  задачи с критериями «сделано правильно»
9. Что читать дальше   →  аннотированные источники
```

### Разметка

Врезки по тексту — это навигация по глубине, а не украшение:

| Значок | Что это | Кому |
|---|---|---|
| 🌱 **База** | минимальный путь через тему | кто видит тему впервые |
| 🧠 **Middle+** | детали, отличающие «слышал» от «понимаю» | кто готовится к глубоким вопросам |
| 💬 **На собеседовании** | реальный вопрос + хороший и провальный ответ | всем |
| 📐 **Разбор формулы** | медленный проход символ за символом | у кого практика есть, а математика пугает |
| ⌨️ **Руками** | микро-задача на код прямо сейчас | у кого теория идёт легче кода |
| ⚠️ **Типичная ошибка** | что делают → к чему приводит → как правильно | всем |

Пример того, как выглядит врезка на собеседовании:

> 💬 **На собеседовании.** Спросят: «Что означает `min_child_weight` в XGBoost?»
> Хороший ответ: это минимальная **сумма гессианов** в листе, а не минимальное число объектов.
> Для регрессии с MSE $h_i \equiv 1$, поэтому сумма совпадает с числом объектов — отсюда путаница.
> Для logloss $h_i = p_i(1-p_i)$, и объекты, в которых модель уверена, вносят почти нулевой вклад.
> Провал: «это минимальное количество объектов в листе».

## Как этим пользоваться правильно

Коротко — полная версия в [методике](docs/00-start/04-study-method.md):

1. **Отвечайте на вопросы вслух до раскрытия ответа.** Открыли ответ сразу — эффект потерян.
2. **Выводы повторяйте на бумаге.** Согласиться с выводом легко, воспроизвести — трудно.
   Разница между этими состояниями и есть разница между провалом и успехом на секции.
3. **Код набирайте руками и ломайте.** Понимание кода — это умение предсказать, что сломается.
4. **Глава без сделанных задач не считается пройденной.**
5. **Возвращайтесь через день, неделю и месяц** — только к блокам «Проверь себя».
